# A 股长期投资趋势判断系统

判断一只 A 股**是否符合长期投资**：用**市盈率 / 市净率 / 股息率**衡量贵贱，用**国家政策红利**衡量
风口，用**美联储潮汐**衡量全球流动性，再把 **GDP / PMI / CPI / PPI** 这套宏观周期拼成一张
「现在是该进攻还是该防守」的背景板——最后输出**个股打分（0~100）＋ 建议总仓位**。

一句话概括设计取向：**先看潮水（宏观→仓位），再看船（个股→选择）**。

## 一、它做了什么

| 层次 | 产出 | 说明 |
|---|---|---|
| 宏观背景 | 背景分 0~100 → 目标仓位 | PMI 30% + PPI 25% + 美联储 20% + CPI 15% + GDP 10% |
| 个股打分 | 0~100 分 + 评级 A+/A/B/C/D | 估值 45% + 质量 30% + 股息 15% + 政策 10% |
| 规则验证 | 回测A | 你提的每条宏观说法，在 2011-2026 上到底成不成立 |
| 组合回测 | 回测B | 按打分选前 N 名等权季度调仓，对比沪深300 |
| **买卖决策** | **回测C + `output/tracking.csv`** | **逐只个股：9 条买入门槛（AND）+ 13 条卖出规则（OR），并跟踪你自己的持仓（见第五节）** |
| 交付 | `output/dashboard.html` | 单文件、零外部依赖、离线可开的看板 |
| 实时刷新 | `--live` / `--live --watch N` | 行情层跟随盘面（分钟级），宏观层受官方公布节奏限制（见「三、实时模式」） |

`requests` 默认不读 IE 代理设置，代码里已显式设置 `HTTP_PROXY` / `HTTPS_PROXY`。

### 网站模式（推荐：打开浏览器就是当前数据）

**最省事的方式：双击工作区根目录下的 `启动网站.bat`。** 它会用
`--refresh 180 --limit 300 --open-stale 30 --quote-interval 15` 起服务并自动开浏览器，
服务日志写在 `output\serve.log`；**关掉那个黑窗口就停止**。

这个 `.bat` 可以**随便反复双击**：它会先探一下 8848 端口，如果网站已经在跑，
就只打开浏览器（不会再起第二个实例抢端口）。所以「打不开」时，双击它永远是安全的第一步。

> ⚠️ **千万不要用「助手起的后台进程」当日常服务。** 助手（AI）启动的任何进程
> 都会在它那一轮任务结束时被一起杀掉——所以你会看到「刚才还能开，过一会儿就
> 打不开」。要让网站长期可用，**必须由你自己双击 `启动网站.bat`**，它跑在你自己的
> 会话里，跟助手无关。
>
> 第一次打开时，前 40~80 秒看到的是「正在准备第一版数据…」页面（**带着完整导航**，
> 不是坏页），算完会自动刷新，不用按 F5。

或者手动起：

```powershell
F:\ana\python.exe scripts\serve.py
```

它会起一个**只监听本机**（`127.0.0.1`）的小网站并自动打开浏览器，地址
`http://127.0.0.1:8848/`。**8 个页面共用同一套外观和顶部导航**（不是一堆散页）：

| 页面 | 内容 |
|---|---|
| `/` **总览** | 现在该做什么：宏观背景分与目标仓位、我的持仓**实时**盈亏、今天要处理的、候选建仓、数据新鲜度 |
| `/pick` **选股·勾选建仓** | 按「建仓 / 接近建仓 / 观望」分三张表，**逐行勾选 + 填买入价与股数 →「加入我的持仓」**（一次提交多只） |
| `/my` **我的持仓** | 录入/修改/删除台账 + **实时**盈亏与卖出提醒（含扣费后净盈利）+ 手续费口径 |
| `/report` **完整报告** | 原来的完整看板（11 个章节都在） |
| `/macro` **宏观与政策** | 宏观规则明细（回测A）+ 政策红利打分依据 |
| `/backtest` **回测** | 个股组合回测（回测B）+ 个股逐笔买卖回测（回测C） |
| `/data` **数据新鲜度** | 每一项数据实际到哪一天、缓存抓取时刻、刷新周期、为什么只能这么快 |
| `/rules` **规则与费率** | 7 条判断条件逐条落地 + 买入/卖出门槛 + 权重 + 费率 |

**两种「更新」是分开的**，这是这个网站的核心设计：

| | 周期 | 更新的东西 |
|---|---|---|
| **秒级报价**（浏览器轮询 `/api/quotes`，默认 15 秒） | 15 秒 | 只重算**钱**：现价、市值、浮动盈亏、扣费后净盈利。页面上带 `data-q` 的单元格**原地改写并闪色**，不整页刷新 |
| **全量重算**（后台线程，默认 180 秒） | 180 秒 | 重出**结论**：宏观背景分、目标仓位、个股打分、买卖决策、报告章节 |

也就是说：你盯着页面看，价格和盈亏每 15 秒自己动；而「该不该卖」这类结论
每 3 分钟重算一次。**结论变了才整页 reload**（此时若你正在输入框里打字，会推迟
刷新并提示「已更新，填完即刷新」，不会把你的输入冲掉）。

**你刚录入的持仓不用等重算**：在 `/pick` 勾选建仓或到 `/my` 手工录入后，
`/my` 的实时盈亏表**立刻**就有这两行（页面渲染时会现读 `config/holdings.csv`
重算一遍台账），最多 15 秒后报价回来数字就填上。在报价到达之前，总市值/浮动盈亏
显示的是「**待报价**」而不是「¥0.00」——后者会被误读成「不赚不亏」，那不是实话。

其它自动行为：
1. **打开页面时**如果数据已超过 `--open-stale` 秒（默认 30），立刻补一轮；
2. 导航栏右侧有**连接状态圆点** + 「实时 N 只 / 报价时间」+「第 N 版 / 正在重算…」；
3. 想看最新的可以点状态条上的「**立即刷新**」，也可以等下一周期。

> ⚠️ 网站上「实时」的是**行情类**数据（价格 / PE / PB / 市值 / 美股汇率）。
> **宏观（PMI/CPI/PPI/GDP）是月度、季度公布的数据，任何网站都不可能让它变快**
> ——`/data` 页会如实标出每一类数据实际到哪一天。

```powershell
# 常用参数
F:\ana\python.exe scripts\serve.py --limit 300        # 打分候选股数量（默认 300）
F:\ana\python.exe scripts\serve.py --refresh 180      # 每 180 秒全量重算一次（默认 180）
F:\ana\python.exe scripts\serve.py --quote-interval 5 # 每 5 秒刷新一次实时报价（默认 15）
F:\ana\python.exe scripts\serve.py --open-stale 0     # 每次打开页面都补一轮（默认 30 秒）
F:\ana\python.exe scripts\serve.py --no-refresh-on-open  # 打开页面不主动补刷
F:\ana\python.exe scripts\serve.py --port 9000        # 换端口
F:\ana\python.exe scripts\serve.py --offline          # 只读缓存，不联网重抓
F:\ana\python.exe scripts\serve.py --no-open          # 不自动开浏览器
F:\ana\python.exe scripts\serve.py --codes 600519,000651 --limit 10   # 只盯几只
```

数据与接口：

| 路径 | 内容 |
|---|---|
| `/api/quotes` | **实时报价**（秒级轮询用）：报价 + 我的持仓按最新价重算的盈亏 |
| `/api/status` | JSON：构建号、数据时间、是否在构建、上次错误 |
| `/api/holdings` | `GET` 读台账 / `POST` 增改删（`action=upsert|delete`） |
| `/api/refresh` | 手动触发一轮全量重算（`POST`） |
| `/report.md` | Markdown 报告，同内容纯文本 |
| `/scores.csv` · `/scores.xlsx` | 个股打分明细，带逐项理由 |
| `/tracking.csv` | 个股买卖决策与跟踪表 |
| `/portfolio.csv` | 我的持仓核算结果（含扣费后净盈利） |
| `/macro_context.json` | 宏观背景分与目标仓位 |
| `/dashboard.html.raw` | 单文件看板原件（不带导航，用于外部引用） |

旧的 `/portfolio` 会 **302 跳到 `/my`**，`/index.html` 跳到 `/`，老书签不会失效。

设计上的几点取舍：

- **结论与价格分离**：`/api/quotes` 只改数字，**不改买卖动作**。动作取决于估值分位与
  总分，要动就得重跑打分——所以页面不会因为盘中价格抖动而给出前后矛盾的"该卖了"。
- **构建失败不会让服务挂掉**。单轮出错只记进 `last_error`，导航栏状态变红，
  下一周期自动重试；**单个页面渲染出错也只会让那一页显示错误信息**，不会打死整站。
- **不会刷新死循环**。补刷完成后 `stale` 归零，再次打开页面就不再触发。
- **构建期间照常可访问**。读到的是上一版完整页面，状态显示「正在重算…」，
  不会出现半成品页面。
- **服务端自己管刷新节奏**，所以会把看板里那条 `<meta http-equiv="refresh">` 去掉，
  避免两套刷新机制打架。
- **不对外网开放**，只绑 `127.0.0.1`；也没做鉴权，因为它本来就不出本机。

> 首次打开可能要等十几秒到几分钟：第一版数据要把行情、估值、财务、宏观都抓一遍。
> 这期间页面显示「正在首次构建数据…」并每 4 秒自动重试，无需手动刷新。

> ⚠️ **改完任何 `touzi/*.py` 或 `scripts/webui.py` 都必须重启 `serve.py`**——
> 它是长驻进程，模块已经在内存里了，不重启就还是旧代码。这个坑踩过两次。

### 公网版（`dist/`：不用开这台电脑，点开网址就能看）

上面那套网站跑在**你自己的电脑**上，所以电脑关了就没了。公网版是把**当前这一版结论
烘焙成一组纯静态网页**，传到免费托管上，之后任何设备打开那个网址都能看——就像一个
普通网站。

**它是什么**：`scripts/publish_site.py` 重新算一遍（宏观 → 打分 → 跟踪表 → 报告），
把 8 个页面导出到 `dist/`。导出后**没有任何后端**，就是一个文件夹：

| 文件 | 说明 |
|---|---|
| `index.html` `pick.html` `my.html` `report.html` `macro.html` `backtest.html` `data.html` `rules.html` | 和本机版同样的 8 个视图、同一套导航与外观 |
| `app.js` | 浏览器里的引擎：直连腾讯行情取实时价、算盈亏与卖出建议 |
| `site.js` | 发布那一刻烘焙进去的结论（每只股票的买卖动作、PE/PB/股息率/触发条件），外加费率 |
| `report.md` `scores.csv` `tracking.csv` `macro_context.json` | 可直接下载的导出文件 |
| `.nojekyll` | 让 GitHub Pages 不要用 Jekyll 处理，避免下划线文件被吃掉 |

**怎么发布（GitHub Pages，用你已有的 GitHub 账号）**：

1. 双击根目录的 **`更新公网网站.bat`**：它重算一遍数据 → 导出 `dist/` → 打包 `dist.zip`
   → 打开 `dist` 文件夹和 GitHub 新建仓库页。
2. 新建仓库（名字如 `touzi`，选 **Public**）→ `Add file` → `Upload files` →
   把 **`dist` 文件夹里的文件全选**拖进去（传的是 `dist` 里面的文件，不是 `dist` 这一层）
   → `Commit changes`。
3. 进 `Settings → Pages`，`Source` 选 `Deploy from a branch`，`Branch` 选 `main`、
   目录选 `/ (root)`，`Save`。
4. 等 1 分钟，网址就是 `https://<你的用户名>.github.io/touzi/`。

**以后更新**：把那个仓库网址填进 `更新公网网站.bat` 顶部的 `set REPO=` 那一行，
之后每次双击它就会直接打开 `.../upload/main`；把 `dist` 里的文件再拖一遍、提交即可
（同名文件覆盖是正常的）。

**想先在本机看看长什么样**（不起 `serve.py`，纯静态）：

```powershell
F:\ana\python.exe scripts\publish_site.py --reuse --serve 8899   # 起静态预览并自动开浏览器
```

**也可以用 Cloudflare Pages**（不需要 git、不需要命令行）：在上传页点
`Create application` → `Pages` → `Upload assets`，把 `dist` 文件夹拖进去，得到
`https://<名字>.pages.dev`。同一份 `dist/` 两边都能用。注意 GitHub Pages **不会**
把 `/pick` 映射到 `pick.html`（Cloudflare Pages 会），所以 `dist/` 里的站内链接一律是
**相对路径**（`pick.html` 而不是 `/pick`）——两边都能用，这是导出时强制改过的。

**数据和本机版有什么不同（这点必须说清楚）**：

| | 本机版 `serve.py` | 公网版 `dist/` |
|---|---|---|
| **价格 / 市值 / 浮动盈亏 / 扣费后净盈利** | 后端每 15 秒重算 | **浏览器每 15 秒直连腾讯重算**（同样是活的） |
| **宏观分、个股打分、买卖动作、预警** | 每 180 秒重算 | **冻结在发布那一刻**（静态站没有后端可以算分） |
| **持仓台账** | `config/holdings.csv` | **浏览器 `localStorage`**，不上传、不公开 |

> 为什么持仓放浏览器：GitHub Pages / Cloudflare Pages 上的东西是**公开的**，把真实
> 持仓写进仓库等于把自己买了什么告诉全世界。所以公网版开局是空的，你在 `/my` 页
> 录进去的持仓只存在**你这台浏览器的本地存储**里。
>
> 换浏览器、清缓存、或者想备份，就用 `/my` 页里的「导出 CSV」按钮存一份，在新浏览器
> 用「导入 CSV」贴回去（导入框接受 `代码,名称,买入日期,买入价,股数,备注`）。
>
> 这也意味着：**要让结论变新，得重新跑一次 `更新公网网站.bat` 并重新上传。** 长期
> 投资场景下，买卖规则本来就不该因为盘中跳动而变——真正的实时部分（你的钱）是活的。

**怎么确认它没坏**（都不联网也能跑）：

```powershell
F:\ana\python.exe scripts\check_static.py         # 起临时静态服务，逐页抓取 + 页面上每个链接都真点一遍
F:\ana\python.exe scripts\check_static.py --live  # 额外跑一次真实行情冒烟（要联网）

# 公网版把费用公式搬到了浏览器里，跟 Python 版必须逐字段一致，否则钱会静默算错：
F:\ana\python.exe scripts\static\ref_portfolio.py --out .tmp\ref.json   # 用 Python 的真实实现出标准答案
node scripts\static\test_engine.cjs .tmp\ref.json                       # 用 Node 跑 app.js 逐项比对（8 用例 × 96 项）
node scripts\static\smoke_quotes.cjs                                    # 真发一次腾讯请求，验证 GBK 解码与算钱链路

# 浏览器里才会跑的那一半（表格渲染、表单、CSV 导入导出、apply 改写单元格）：
node scripts\static\test_dom.cjs                                        # 极简 DOM + 伪造行情，34 项断言
```

> 上面最后一条是**必须**的：`check_static.py` 只看静态 HTML，看不见
> `renderLedger/renderLive/renderKpi/apply` 这些只在浏览器里执行的函数。它们写错的话
> 页面会是一片空白，而静态自检照样全绿。这条测试第一次跑就抓出了 3 个真 bug
> （合计行永不刷新、两条自调度链、每 15 秒白重画整张表）。

> 改完 `scripts/static/app.js` 记得**重跑 `publish_site.py`**：`dist/app.js` 是拷贝过去的，
> 不会自动跟着变。

> ⚠️ 公网版依赖**腾讯行情接口允许跨域**（`qt.gtimg.cn` 返回
> `Access-Control-Allow-Origin: *`，已实测）。哪天它把这个头去了，公网版的「实时」
> 就会失效——页面会显示「取报价失败」而不是编一个数字出来。本机版不受影响，因为
> 它由自己的后端去取。

### 命令行模式（`--live` / `--watch`）

如果你不想开网站，也可以让命令行自己循环、直接覆盖 `output/dashboard.html`：

系统默认是**离线模式**：数据抓一次进本地 `data_cache/`，默认 TTL 内直接复用，
保证结果可复现、断网也能跑。要让它跟着盘面走，加 `--live`：

```powershell
# 单次实时刷新：每次运行都重抓行情，决策时点 = 今天
F:\ana\python.exe scripts\run_all.py --live --limit 300 --reuse-backtest

# 盘中循环刷新：每 300 秒重算一次，output/dashboard.html 被原地覆盖
F:\ana\python.exe scripts\run_all.py --live --watch 300 --limit 300 --reuse-backtest
```

`--live` 做的事（`[realtime]` 段可改）：

| 数据 | 离线 TTL | 实时 TTL | 说明 |
|---|---|---|---|
| 行情快照（价格 / PE-TTM / PB / 市值） | 1 天 | **3 分钟** | 真正实时的只有这一层，且盘后才重抓没有意义 |
| 个股估值历史 / 指数日线 / 国债收益率 | 1 天 | **30 分钟** | 日频数据，盘中重抓也拿不到新点 |
| 美股 / 美元指数 / 美债利率 | 7 天 | **30 分钟** | 隔夜为主，但盘中也在变 |
| 中国宏观（PMI/CPI/PPI/GDP/M2） | 7 天 | **6 小时** | **月度/季度公布，永远做不到实时** |
| 个股财务 / 分红 / 行业归属 | 30 天 | **1 天** | 季度与事件驱动 |

`--watch` 建议配合 `--reuse-backtest`：回测是历史研究，不需要跟着盘中重算
（重跑一次回测B 要几十分钟）。不加 `--offline`/`--live` 时按配置里的
`[realtime] enabled` 走。

> ⚠️ **宏观部分不可能实时**。PMI 是当月最后一天公布、CPI/PPI 是次月中旬、GDP 是季后
> 三周，这是官方节奏，任何系统都不能提前拿到。看板里的「数据新鲜度」一节会逐项列出
> 每类数据**最新到了哪一天**、**本地是什么时候抓的**、**多久刷一次**，不会假装实时。

> ⚠️ **必须设 `PYTHONIOENCODING=utf-8`**，否则控制台按 GBK 编码时会因为源文件里的
> 全角标点抛 `UnicodeEncodeError`。另外系统里的 `pyarrow / bottleneck / numexpr` 是
> NumPy 1.x 时代编译的，每次导入都会往 **stderr** 喷一大段 ImportError——这是噪音，
> 重定向时请用 `> out.txt 2>$null` 分开，否则真正的输出会被淹没。

## 五、买卖规则与持仓跟踪（个股级）

从这一版开始，系统不再只给「组合分数」，而是对**每一只个股**回答三个问题：
**现在能不能买、什么时候该卖、我手上这笔该怎么办**。规则全部写在 `config/settings.toml` 的
`[plan]` 段里，改阈值不用改代码。

### 5.1 买入门槛（8 条 AND + 1 条可选，全过才建仓）

| # | 条件 | 默认阈值 | 含义 |
|---|---|---|---|
| 1 | 总分 | ≥ 72 | 综合评分够高 |
| 2 | 质量分 | ≥ 60 | ROE / 现金流 / 负债不能太差 |
| 3 | **PE 自身历史分位** | ≤ 0.40 | 比它自己过去 5 年 60% 的时间都便宜 |
| 4 | **PB 自身历史分位** | ≤ 0.40 | 同上，看净资产口径 |
| 5 | **股息率** | ≥ 2.0% | 有真金白银的分红 |
| 6 | PE 绝对值 | ≤ 40 | 再便宜也不碰亏损/畸高估值 |
| 7 | **PE × PB（格雷厄姆数）** | ≤ 50 | 见下方说明，**不是**教科书的 22.5 |
| 8 | 宏观背景分 | ≥ 45 | 大盘环境不能是防御/保守 |
| 9 | 候选池内排名 | 默认关闭 | 见下方说明 |

差 1 条以内记为**「接近建仓」**，会一起列进跟踪表——这是最容易先动手的一批。

**关于 PE × PB ≤ 50**：格雷厄姆原文的 22.5（PE≤15 且 PB≤1.5）是给 1930 年代美股定的
深价值线，直接套到 A 股会把绝大多数公司挡在门外。本系统候选池的 PE×PB 实测分位是
`5%→4.3、10%→6.4、20%→14.1、30%→24.0、40%→39.4、50%→61.8、75%→217.9、90%→1060.7`，
**中位数约 62**。所以买入线定在 50（约 40% 分位以内），卖出线定在 120。
教科书那个 22.5 仍然保留在 `[valuation] graham_number` 里，作为估值打分里的
「估值优秀」标记继续参与评分，只是不再当作硬门槛。

**关于排名门槛**：它算的是「在**本次已打分的候选池**内的名次」，池子大小一变
（`--limit 24` vs `--limit 600`）绝对含义就变了。做成硬门槛会让结论随运行参数漂移，
所以默认关闭（`buy_max_rank_pct = 0.0`）。

### 5.2 卖出门槛（OR，任一触发就动手）

| 级别 | 条件 | 默认阈值 |
|---|---|---|
| 清仓 | PE 自身历史分位 | ≥ 0.80 |
| 清仓 | PB 自身历史分位 | ≥ 0.80 |
| 清仓 | PE × PB | ≥ 120 |
| 清仓 | PE 绝对值 | ≥ 60 |
| 清仓 | 股息率 | ≤ 1.0% |
| 清仓 | 总分 | ≤ 62 |
| 清仓 | 宏观背景分 | ≤ 30 |
| 清仓 | 现金流/净利润 | ≤ 0.50 |
| 清仓 | 净利润连降 | ≥ 2 个年报 |
| 减仓 | 总分 | ≤ 67 |
| 减仓 | 宏观背景分 | ≤ 40 |
| 清仓 | 止损（相对成本） | ≤ −25% |
| 清仓 | 止盈（相对成本） | ≥ +150% |

**减仓只做一次**：同一轮建仓里，「总分 ≤ 67 / 宏观 ≤ 40」只触发一次减半，
之后要等「加仓」把标记复位。原因在回测里暴露得很清楚——原先这条会月月触发，
每次卖掉剩余仓位的一半，仓位几何衰减到几乎归零，等于被反复割肉：
招商银行在 2024-04 ~ 2025-11 被减了 7 次，策略收益 34.40%，而同期买入持有 56.41%。
改成「只减一次」后，同一只变成 45.56%，少亏了 11 个百分点。

### 5.3 怎么用（跟踪）

```powershell
# 1) 第一次运行会生成台账模板，照格式填你自己的持仓
F:\ana\python.exe scripts\track.py --limit 300 --top 40

# 2) 填 config\holdings.csv（代码,名称,买入日期,买入价,股数,备注）
#    代码写 600519 或 sh600519 都行；模板里的示例行代码不是 6 位数字，会自动跳过

# 3) 再跑一次，得到建议动作表
F:\ana\python.exe scripts\track.py --limit 300 --top 40 --live
```

输出 `output\tracking.csv` 与 `output\tracking.xlsx`，按动作分组：
**清仓 / 减仓 / 加仓 / 建仓 / 接近建仓 / 持有 / 观望 / 回避**。
持仓股永远排在前面且不受 `--top` 限制；台账里有、但打分结果里没有的（例如停牌）
会标成「无法评估」，不会静默消失。

### 5.4 个股逐笔回测（回测C）——以及它现在告诉我们的实话

```powershell
F:\ana\python.exe scripts\backtest_stocks.py --limit 100 --months 36
```

它将每只股票按同一套规则独立模拟（**次日收盘价**成交，单边成本 0.15%），
输出每笔买卖的明细与原因。2023-10-31 ~ 2026-09-30、100 只大市值股票的实测结果：

| 指标 | 数值 |
|---|---|
| 总交易笔数 / 真正买过的股票数 | 34 笔 / **13 只**（100 只里只有 13 只曾满足买入门槛） |
| 胜率 | 82.4% |
| 平均单笔收益 | +14.45% |
| 有交易的股票：平均策略收益 vs 平均买入持有 | **+26.54% vs +38.21%**（同口径，**跑输 11.7 个百分点**） |
| 全池买入持有：平均 / 中位数 | +187.20% / +55.13% |
| 平均策略收益（没买的记 0） | +3.45% |

按卖出原因的实测（这笔账最能说明问题）：

| 卖出原因 | 笔数 | 平均收益 |
|---|---|---|
| [减仓] 宏观背景分 ≤ 40（偏防御） | 11 | +10.05% |
| 回测期末仍持有 | 9 | +9.50% |
| [清仓] PE 回到自身历史分位 ≥ 80% | 5 | +27.20% |
| [减仓] 总分 ≤ 67（压力位，先减一半） | 4 | +23.64% |
| [清仓] PB 回到自身历史分位 ≥ 80% | 2 | +27.62% |
| [清仓] 总分 ≤ 62（B 级，买入理由不再成立） | 2 | +20.91% |
| [清仓] 相对成本浮亏 ≤ −25%（风控止损） | 1 | −32.53% |

> **这张表要分两个口径读，别被 187% 吓到。**
> 「平均买入持有 187%」是被 新易盛、寒武纪、中际旭创 这类 2023–2026 年 AI 行情赢家
> 拉起来的，而候选池是按**今天的**流通市值排的 —— 当年无法预知谁会涨这么多，
> 所以这是个**带后见之明的基准**，不代表本该赚到的钱。换成中位数只有 +55%。
>
> **真正的结论有三条，都不太好看，但都是真的：**
> 1. 这套门槛很保守 —— 三年里 100 只大市值只有 13 只敢下手，**错过了大盘的普涨**
>    （池子中位都 +55%）；
> 2. 在它敢下手的那 13 只上，**策略跑输买入持有 11.7 个百分点**
>    （+26.54% vs +38.21%）—— 也就是说，**当前这套卖出规则是在削峰，而不是在避险**；
>    触发最多的是「宏观背景分 ≤ 40 就减仓」，11 笔平均只赚到 +10.05%，而那些"卖掉"的
>    仓位后来又涨回去了；
> 3. 表现最好的是**估值型卖出**（PE/PB 分位 ≥ 80% 清仓，平均 +27%），
>    最差的是止损（−32.53%）和宏观减仓 —— 这暗示卖出规则应该以**个股估值**为主、
>    少用宏观背景分去动个股仓位。
>
> 这是个「宁可错过、不肯买贵」的策略，符合长期价值取向，但你要清楚它的机会成本。
> **卖出规则还需要继续调**，这一版的价值在于把问题量化出来了。

### 5.5 个人持仓：录入 → 跟踪 → 卖出提醒（网页上操作）

打开网站后，点左下角的「**✎ 我的持仓 / 录入与提醒**」，或直接访问
`http://127.0.0.1:8848/portfolio`。这一页解决的是「**我手上这笔怎么办**」：

1. **录入**：填 代码 / 名称 / 买入日期 / 买入价 / 股数 / 备注 → 点「保存并重算」。
   同一只股票**分批买入就写多行**，系统按**加权平均成本**合并（键是
   「代码 + 买入日期 + 买入价」：三者全同则覆盖原行，否则新增一行）。
2. **跟踪**：每次重算都会刷新现价、市值、浮动盈亏与浮动盈亏%。
3. **提醒**：到卖出条件时给出 `建议动作`、`建议卖出%`、`建议卖出股数`。
   清仓 = 全部；减仓 = `[plan] reduce_ratio`（默认 **50%**）折算并向下取整到 100 股
   （A 股卖出允许零股，不足一手的按实际股数卖）。
4. **算钱**：`到账金额` 与 `扣费后净盈利` 都按 A 股真实费率算，费率在
   `config/settings.toml` 的 `[fees]` 段：

| 项目 | 默认值 | 收费方向 |
|---|---|---|
| 佣金 | 0.025%（**单笔最低 ¥5**） | 买、卖双向 |
| 印花税 | 0.05% | **仅卖出**（2023-08-28 起由 0.1% 减半） |
| 过户费 | 0.001% | 买卖双向 |

> `扣费后净盈利` = 卖出到账金额 − 该部分对应的**含费成本**（买入佣金也在成本里）。
> 所以**小额买入会被最低 5 元佣金明显拖累** —— 这是真实情况，不是 bug。
> 每家券商费率不同，请按你的对账单改 `[fees]` 后重算。

录入的数据存在 `config/holdings.csv`（就是命令行模式的同一份台账），
结果写在 `output/portfolio.csv`；看板第五节「我的持仓」会把同一份内容
（汇总徽章 + 📣 需要处理的清单 + 全表 + 手续费口径）也渲染进报告。
持仓为空时两处都给空态提示，不会断章节号。

**命令行版本**（不开网站也能用）：

```powershell
F:\ana\python.exe scripts\track.py --limit 300 --top 40 --live   # 写 output\portfolio.csv 与此表
```

## 六、你提的 7 条判断条件：落地方式与**历史验证结论**

| 3 | 美联储潮汐 | **短端成立** | 涨潮 3 月 +1.36% / 胜率 54.3%；退潮 3 月 −1.08% / 胜率 39.5% |
| 4 | PMI >50 或上升 → 涨；GDP 正相关 | **部分成立、部分证伪** | PMI≥51.5 的 12 月 +7.22%（基准 5.76%）；但 PMI<50 时 3 月胜率高达 75.9%，**比扩张期更好**。GDP 高于均值时 12 月 +0.86%，低于均值时 +8.09%——**正相关在 A 股不成立** |
| 5 | CPI 涨得快利好股市 | **被证伪（方向相反）** | 涨得快 3 月 −2.20% / 胜率 39.3%；涨得慢 3 月 +4.05% / 6 月 +5.44% |
| 6 | PPI 下跌到一半，股市领先上涨 | **强烈成立** | 回撤 35%~65% 区间：12 月 **+22.36%** / 胜率 **69.8%** |
| 7 | PPI 到底部时股市已到顶峰 | **成立** | 回撤≥85% 时 12 月 −0.51%；PPI 高位（回撤<35%）时 12 月 −6.99% / 胜率 30% |

**要点解读**

- **PPI 是全部规则里区分度最强的**，你这条直觉非常准，所以宏观权重给到 0.25，并且用
  **钟形曲线**而不是单调打分：分数在「回撤到一半」达到峰值 95 分，到「逼近底部」掉回 15 分。
- **CPI 与直觉相反**，原因是 A 股的定价链条是「通胀上行 → 货币收紧 → 杀估值」。
  模块仍按你的规则保留，但报告和看板都标注了证伪。
- **PMI 的逆势效应**提示 A 股对「坏消息 → 政策宽松 → 估值修复」的定价很强，
  所以 PMI 模块拆成**水平项**（越高越好）和**动量项**（在上行就给分），而不是简单「>50 就买」。
- **GDP 与股市正相关在 A 股不成立**，同样是因为弱增长往往对应强政策预期。

## 七、防未来函数

这是回测能不能信的前提，做了四件事：

1. **宏观公布滞后对齐**：PMI 当月最后一天公布（滞后 0 月），CPI / PPI / GDP 各滞后 1 个月。
   T 时刻的分数只喂 T 时刻**已经能看到**的数字。
2. **个股历史分位**：滚动窗口，只使用当期及之前的数据。
3. **组合回测走 point-in-time**：按 `point_in_time=True` 取调仓日当天的 PE / PB / 股价，
   并**关闭截面分位**（没有历史全市场快照）。
4. **政策事件过滤**：`date > as_of` 的事件不参与打分。

## 八、必须知道的偏差与数据源陷阱

**三个回测偏差**（会让结果偏乐观）：

- **幸存者偏差**：以「当前在市」的股票回溯历史，已退市 / 被并购的票不在样本里，**会高估收益**。
- **估值历史深度不足**：百度估值接口只给近 5 年，更早的季度算不出个股历史分位，早期样本偏少。
  组合回测起点因此落在 2023-12（取 60% 候选股都有数据的时点），只有 11 期。
- **截面分位缺失**：point-in-time 模式下没有历史全市场快照，只能退化为个股自身历史分位。

**三个数据源自身的坑**（踩过并已修正 / 已知残留）：

- **行业归属会过期**：新浪板块对更名或借壳重组的公司停留在旧行业——`002555 三七互娱`
  （原顺荣股份，做汽车部件）仍被归入「汽车制造」，`002558 巨人网络`（原世纪游轮）仍被归入
  「酒店旅游」。这会连带影响政策分和行业中性比较，看板已原样披露。
- **现金流列的量纲**：新浪「经营现金净流量与净利润的比率(%)」这一列的取值**本身就是倍数**，
  不是百分数。若按字面 ÷100，会把好公司全判成垃圾。已用 5 只股票逐年手算核对（茅台 2025 年
  报 0.7212、工行 5.0990、招行 2.9873，与「每股经营现金流 ÷ 每股收益」恒等）。
- **ROE 是年内累计口径**：茅台 2025 年 ROE 依次是 3-31 → 10.39、6-30 → 19.03、9-30 → 25.14、
  12-31 → 33.65，跨期求均值毫无意义。代码只对**年报行**取均值。

## 九、数据源与本机网络限制

本机（2026-10 实测）**不可达、已绕开**的源：

- **FRED**（`fred.stlouisfed.org`）→ 美联储数据改用 **Yahoo Finance** chart 接口
- **东方财富 push2 系**（`push2.eastmoney.com` 及各分片）→ 所有 `*_em` 接口弃用，
  改用腾讯（`stock_zh_a_spot_tx`）、新浪（`stock_zh_a_daily` / `stock_sector_detail`）、
  百度（`stock_zh_valuation_baidu`）
- **申万官网**（`www.swsresearch.com`）→ 个股申万行业归属改用新浪行业板块
- **金十数据日历源**（`macro_china_pmi_yearly` 等）→ 数据陈旧整一年，改用新浪 `macro_china_*`
- 百度估值接口**没有股息率**，股息率由分红明细（新浪「派息」列 ÷ 10 = 每股派息）自行计算

结果：宏观数据新鲜到 **2026-09**，行情到 **2026-09-30**。

## 十、日常使用

```powershell
# 网站模式：打开浏览器就是当前数据，后台自动刷新（最省事）
F:\ana\python.exe scripts\serve.py

# 只改政策表后重跑报告（复用已有回测，最快）
F:\ana\python.exe scripts\run_all.py --limit 600 --reuse-backtest

# 只算几只股票，看逐项理由
F:\ana\python.exe scripts\run_all.py --codes 600519,000651,601398 --skip-backtest --limit 10

# 指定决策时点做「当时会怎么判」
F:\ana\python.exe scripts\run_all.py --as-of 2024-06-28 --limit 300

# 实时：单次刷新 / 盘中每 5 分钟刷新一次
F:\ana\python.exe scripts\run_all.py --live --limit 300 --reuse-backtest
F:\ana\python.exe scripts\run_all.py --live --watch 300 --limit 300 --reuse-backtest

# 个股买卖决策与持仓跟踪（不跑回测，几秒出结果）——详见第五节
F:\ana\python.exe scripts\track.py --limit 300 --top 40 --live

# 个股逐笔回测（回测C，较慢：40 只 × 36 个月约 6 分钟）
F:\ana\python.exe scripts\backtest_stocks.py --limit 40 --months 36

# 报告结构自检（章节号是否连续、有无外链、跟踪表行数）
F:\ana\python.exe scripts\check_report.py
```

改买卖规则：编辑 `config/settings.toml` 的 `[plan]` 段（每个阈值都有注释，见第五节）。
改持仓：编辑 `config/holdings.csv`（代码写 `600519` 或 `sh600519` 都行，示例行会被自动跳过）。
改权重：编辑 `config/settings.toml`（每个阈值都有注释）。
改政策：编辑 `config/industry_policy.csv` / `config/policy_events.csv`。
改实时刷新节奏：编辑 `config/settings.toml` 的 `[realtime]` 段。

> 单次 `--live` 全量（`--limit 300`）首次约 1~3 分钟——瓶颈是重抓全市场行情快照
> 与每只股票的估值历史，不是打分本身。
