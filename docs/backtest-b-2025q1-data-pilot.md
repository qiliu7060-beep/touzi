## 可行补数路径与验收条件

### 路径A：先取得供应商小批实数，按原公告核验后扩展

1. **历史池与日截面**：Tushare `bak_basic(trade_date='20250331')`文档称2016年起、每次最多7000行、正式权限5000积分；可候选性获取当日名称/行业/上市日期。结合`stock_basic`的L/D/P状态查询、`daily_basic`的当日流通市值及`pe_ttm/pb`、历史名称和ST事件、未复权成交额，按当时规则重建并冻结池。`stock_basic`的当前行业不能代替历史行业。必须分市场核对行数、补齐分页/缺失证券并留排除原因；没有当日交易数据不等于退市或不在池。
2. **历史估值**：`daily_basic`有日期、pe_ttm、pb、circ_mv，官方文档列2000积分起。但文档没有证明历史值从不事后重算，也不证明更正后是否覆盖旧值。必须取得实际导出及供应商修订/历史版本说明，再选原公告跨日窗口交叉核对。仅通过价格/财报自行重建PE不能冒充本契约要求的原始历史估值。估值历史长度须满足既有评分窗口，不能只导出3月31日一天；优先请求2020-03-31至2025-03-31，并实测已有分位逻辑的有效覆盖。
3. **财报版本**：米筐RQData `get_pit_financials_ex`当前文档明确支持`date`和`statements='all'`，返回`info_date`、`if_adjusted`；比只有报告期的接口更贴近契约。请求截至2025-03-30的原生三表全部版本（本实现不接受信号当日新披露），并扩展足够年报区间；派生ROE/增速仍须按现有定义映射。先拿茅台2022/2023追溯调整案例核对原版本和披露日期，再谈批量验收。接口名称带PIT也不能自动认证导出。
4. **分红及公司行动**：Tushare `dividend`文档有`imp_ann_date/ex_date/cash_div_tax`，不能把预案日`ann_date`直接当最终实施版可用日；巨潮/交易所原公告负责事件版本核对。`adj_factor`为供应商自行生产，须对实际事件日比对，特别是27.673/27.600差异化分红。自上市以来的完整性不能仅从一次API返回成功推断。
5. **价格/状态/基准**：同一供应商导出未复权daily、adj_factor、suspend_d、涨跌停/交易限制和000300指数日线及交易日历，逐日核对覆盖。`suspend_d`文档2000年起，仍须实数验证跨月连续停牌覆盖；未知缺行继续拒算。先确认中证/上交所指数代码映射，不把任何000300同名序列直接混入。

本次没有登录、购买、提交API查询凭据，也没有实际取得上述认证API历史导出。文档能确认接口能力和字段，不能确认本账号权限、2025年样本覆盖率、原始版本保留或获取成本。请求权限和价格以供应商当前实际授权为准。

## 避免后续重复误报的落地建议（尚未实施）

- 原始下载只追加，按SHA-256固定；公告版本、披露日期、报告期与抓取时间分别保存。相同业务键值发生变化保留两版并阻止自动认证。
- 每次数据批次出具候选池完整性、披露版本、估值口径、公司行动、日历/价格缺行检查。认证记录引用证据ID及审核人/时间；校验器不得自行把验证标志置True。
- 证据不足保持`not_computed`，只报告缺口变化；不得复用旧收益、不更改生产参数绕过限制。
- 数据完整通过后才用现有入口离线跑首个样本，再冻结输入、环境、配置、输出和审计哈希，重复运行比较结果。
- 这些措施可阻止未知数据被当作已验证数据使用，无法保证供应商永不缺失或修订。历史数据缺口不是修改算法即可永久消除的问题。

## 本地复核（原取证包操作说明）

以下为原取证包的复核方法，本次仓库审查未执行该脚本。

运行`python verify_bundle.py`只校验冻结文件字节及样本基本约束，不连接网络，不运行收益，也不认证历史版本。下载脚本是本次GET取证记录，重跑会取得当前版本，不能用来覆盖本次冻结材料。`SHA256SUMS`覆盖所有本次交付文件（自身除外）。
