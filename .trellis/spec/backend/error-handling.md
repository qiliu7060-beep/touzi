# 错误处理与降级

## 按边界分类

### 必须失败

- 配置文件不存在或关键数据集完全不可用：抛出 `FileNotFoundError` / `RuntimeError`，让入口返回非零退出码。
- 回测没有足够数据、没有调仓期或没有有效结果：`touzi/backtest.py` 明确拒绝输出伪结果。
- 发布行情日期、最小报价时间或覆盖率不达标：`scripts/publish_site.py` 必须拒绝发布旧评分。

## 场景：延迟定时任务跨越北京时间零点

### 1. 范围 / 触发条件

GitHub Actions 的 `schedule` 可能排队到北京时间次日凌晨。发布门禁必须区分“执行自然日”和“有效收盘时段”，但不能把任意旧行情当成最新数据。

### 2. 函数签名

```python
validate_quote_freshness(
    flags: dict,
    min_quote_time: str,
    now: datetime | None = None,
) -> list[str]
```

返回空列表表示可以发布；返回一个或多个中文错误表示必须拒绝发布。`main()` 收到非空错误列表后返回退出码 `1`。

### 3. 输入契约

- `flags["quote_at"]`：北京时间字符串，格式严格为 `YYYY-MM-DD HH:MM`。
- `flags["quote_coverage"]`：具有真实报价的候选股比例，必须不低于 `0.90`。
- `min_quote_time`：调用方要求的当日最早报价时间，当前 workflow 只传 `09:30` 或 `15:00`。
- `now`：确定性测试入口；无时区时按北京时间解释，有时区时先转换到 `Asia/Shanghai`。
- 跨日窗口：依据`config/trading-calendar.json`的已核验交易日历，在休市及开盘前接受最近有效交易日不早于`15:00`的完整收盘行情。未知年度/无法确定最近交易日拒绝；不能根据行政调休推断开市。
- 跨日例外不能绕过 `min_quote_time`、未来 5 分钟容差或覆盖率校验。

### 4. 校验与错误矩阵

| 条件 | 结果 |
|---|---|
| 同日行情且满足其他门槛 | 允许 |
| 下一交易日 `09:30` 前或经公告确认休市 + 最近交易日完整收盘 | 允许，同时保留真实来源时间 |
| 下一交易日恰好 `09:30` 或更晚 + 上个交易日行情 | 拒绝：不在当前有效交易窗口 |
| 休市/盘前基线未到 `15:00` | 拒绝：不完整收盘 |
| 报价不是日历推导的最近有效交易日、或日历未覆盖 | 拒绝：不在已核验日历有效窗口 |
| 行情早于 `min_quote_time` | 拒绝：报价时间过早 |
| 行情晚于当前时间超过 5 分钟 | 拒绝：未来时间不可信 |
| `quote_coverage < 0.90` | 拒绝：真实报价覆盖率不足 |
| `quote_at` 缺失或不可解析 | 拒绝：未返回真实报价时间 |

### 5. Good / Base / Bad

- Good：当前 `2026-10-14 01:00`，行情 `2026-10-13 16:14`，覆盖率 `1.0`，收盘门槛 `15:00` → 允许。
- Base：当前 `2026-10-13 17:23`，行情 `2026-10-13 15:00`，覆盖率 `0.97` → 允许。
- Bad：当前 `2026-10-14 09:30`，行情 `2026-10-13 16:14` → 拒绝。
- Bad：当前 `2026-10-14 01:00`，行情 `2026-10-13 14:59` → 拒绝。

### 6. 必需测试

`tests/test_score_quote_freshness.py`及交易日历矩阵必须固定`now`，覆盖跨日、周末/长假、下一开盘`09:29`/`09:30`、不完整收盘、错误交易日、未知年度、未来`+5`/`+6`分钟、覆盖率`0.89`、空值及错误格式。

### 7. 错误与正确实现

错误：直接要求 `quote_at.date() == current.date()`，这会把延迟到次日凌晨的有效收盘行情误判为过期。

正确：同日行情正常校验；跨日只允许经核验交易日历确定的最近交易日完整收盘，下一开盘后立即失效，并独立执行最小时间、未来容差和覆盖率门槛。

### 可以局部降级

- 沪/深列表一侧失败时保留另一侧并警告；两侧都失败才中止，见 `touzi/data/stock.py::fetch_stock_list()`。
- 单只股票、单批报价或单个宏观序列失败时记录对象和原因，继续处理其余项；必要集合全部失败才中止。
- 在线抓取失败但有缓存时返回旧缓存，并记录缓存年龄；下游仍需保留新鲜度状态。

## 异常边界

- 只捕获预期异常时使用窄类型，如 `TypeError`、`ValueError`、`sqlite3.IntegrityError`。
- 网络/第三方库边界允许 `except Exception`，但必须加上下文并决定“跳过、缓存降级或中止”，不能空吞。
- 使用 `raise ... from exc` 保留根因链；`accounts.py` 将 SQLite 唯一约束转换为用户可理解的 `AccountError` 是参考模式。
- 解析可选展示字段时可以退回 `None`/`NaN`，但核心决策输入缺失时不得默认为通过。

## 未知状态

本项目最重要的安全规则是“未知不等于正常”：

- 无报价 → 不计算市值/盈利，不显示 0。
- 缺少自身历史分位 → 不能用行业分位冒充买入门槛已知。
- 卖出所需数据缺失 → `无法评估` 或预警，不返回“一切照旧”。
- 旧评分 → 可展示旧日期，但不能触发确定性交易建议。

## CLI 与服务

- CLI `main()` 返回整数并由 `raise SystemExit(main())` 统一转换退出码。
- 单轮后台刷新失败只更新错误状态，保留上一版页面并允许下周期重试。
- HTTP 层向用户返回稳定消息；内部 trace 写日志，不直接暴露密码、token、SQL 或第三方原始响应。

## 禁止做法

- `except Exception: pass` 或无日志返回空 DataFrame。
- 为了让流水线变绿而把发布新鲜度失败改成成功。
- 用 0、空字符串或空数组同时表示“真实为空”和“抓取失败”。
- 对结果未知的外部写操作自动重试。
