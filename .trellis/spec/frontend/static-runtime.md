# 静态站运行时规范

## 数据与决策边界

`scripts/static/app.js` 只在浏览器中更新行情、金额和与个人买入成本相关的止损/止盈；公共宏观分、个股评分和规则快照来自发布时生成的 `site.js`。不得用一次实时报价在浏览器里重新发明整套评分模型。

Sites 的 `webapp/public/legacy/app.js` 另外通过 `/api/scores/live` 读取 Worker 依照 Python 真实输入计算的动态评分。这是服务端可验证镜像，不是浏览器新增模型。独立部署、输入校验、逐股行情时间及发布门禁见 [动态评分契约](../backend/live-scoring-contract.md)。

公开评分必须先通过 `publicScoreFresh()` 的日期、报价时间和覆盖率校验。旧评分只能显示为待核验或无法评估，不能继续触发确定性的清仓/减仓结论。

## 与 Python 保持逐字段一致

下列 JavaScript 逻辑是 Python 业务规则的镜像：

- `txSym()` / 腾讯字段表 `F` ↔ `touzi/data/stock.py`。
- `commission()`、`buyFees()`、`sellFees()`、`planSellShares()`、`oneRow()` ↔ `touzi/portfolio.py` 的 `FeeModel` 与 `Portfolio._one()`。
- 页面 `data-q="代码.字段"` 协议 ↔ `scripts/webui.py` 的实时报价改写逻辑。

修改任何一侧时，必须搜索并核对另一侧。金额公式不能只凭“结果看起来合理”验收，必须运行 Python 标准答案与 Node 实现的逐字段比较。

## DOM 与状态

- 公网个人台账只存在 `localStorage`，键名保持 `touzi.ledger.v1`，除非同时提供迁移逻辑。
- DOM 更新应围绕已有 `data-q` 标记和渲染函数，不要并行建立第二套定时器或全表重绘链。
- 报价缺失时用 `null`/“待报价”语义，不能把未知金额显示成 `0`。
- 腾讯接口失败、GBK 解码降级和部分股票缺失都必须保留可见错误信息。
- Sites 动态列在首个请求返回前显示待核验，不得先把发布快照标成动态分；每 15 秒行情和每 60 秒评分使用同一调度链，隐藏时暂停、恢复时补查。
- 卖出提醒仅当前账户和页面内存持有。完整核验恢复后再允许重新提醒；部分缺失时保留上次风险并标待核验，不能假定已经解除。

## 持仓操作与企业选择

- 编辑使用页内dialog，以打开时完整台账快照核验目标；修改代码、日期或价格仍替换指定记录，不能复用新增买入的upsert键来决定编辑身份。取消不写入。
- 删除按钮的inline onclick只传数字索引，不把JSON字符串直接嵌入HTML双引号属性；否则前导零股票代码的双引号会截断处理器。回归测试需解析实际渲染按钮处理器，而不能仅直接调用全局函数。
- 所有写入口（新增、编辑、删除、导入、清空、选股加入）使用候选台账和同页提交锁。持久化成功才提交可见LEDGER；静态站localStorage失败保留原数据，Sites云端网络/5xx的结果不确定时阻止继续写入并要求刷新核验，不自动重放。
- 云端写入设15秒超时，超时属于结果未确认；写入成功后的渲染错误须提示“已保存，请刷新”，不能误报保存失败。弹窗关闭恢复原焦点，原行按钮因重绘移除时回到f_code输入框。
- 企业财务搜索按当前ENTRIES的中文名称或代码匹配；多结果须明确选择，未匹配不得切换；中文组合输入回车不提交。定时刷新保留查询和选择，不以名称推断未覆盖企业的财报。
- 年度说明必须符合Python契约：每年5月1日起五年窗口向前滚动；工作日任务检查报告及更正，实际获取时间独立显示。浏览器不能凭当前年份覆盖后端window或宣称披露后实时可用。

## 生成与同步

`scripts/publish_site.py` 负责复制 `scripts/static/app.js`、生成 `site.js` 和八个页面，并执行结构校验。源文件修改后用发布脚本重新生成，不手工修补 `dist/`。

`webapp/public/legacy/` 有独立测试（`webapp/scripts/test-*.mjs`）。如果发布流程需要同步静态站产物到 legacy，必须把同步步骤做成可重复命令并测试，不能依赖人工复制。
